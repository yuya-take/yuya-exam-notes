# Exam Retro

受験後の振り返りを記録する。ディレクトリ構成は CLAUDE.md に従う。

**守秘義務:** 多くの資格は、受験時に試験内容の守秘に同意している。本番の問題・選択肢・「この論点が出た」という具体的な内容は、聞かないし書かない。記録するのは、手応え、時間配分、ドメイン単位の評価、学習方法の良し悪しまで。ユーザーが問題の内容を話し始めたら、記録しないことを伝える。

## Step 1: 聞く

`AskUserQuestion` で、1回にまとめて聞く。
1. **結果:** 合格 / 不合格 / まだ発表されていない
2. **時間配分:** 余った / ちょうど / 足りなかった
3. **苦しかったドメイン（複数選択）:** README のドメインから選ぶ（4つを超えるときは、比重の大きい順に3つと「Other」）
4. **役に立った学習（複数選択）:** ノート / 練習問題 / 模擬試験 / 手を動かす演習

スコアレポートにドメイン別の評価（例: 「十分」「要改善」）があれば、ドメイン名と評価だけを教えてもらう。点数の数値は、ユーザーが残したいと言ったときだけ記録する。

## Step 2: 記録する

`<exam>/retro.md` に追記する（ファイルが無ければ `# 受験の振り返り` という見出しで作る）。

```markdown
## <YYYY-MM-DD> 受験 — <合格 / 不合格 / 発表待ち>

- 時間配分: <>
- 苦しかったドメイン: <>
- ドメイン別の評価: <ドメイン名: 評価>（スコアレポートより）
- 役に立った学習: <>
- 次に向けて: <1〜3行>
```

## Step 3: 結果に応じて更新する

`exam-researcher` エージェントに、更新・再受験の規定を調べさせる。

**合格のとき:**
- `<exam>/README.md` の試験概要に、次の行を足す
  - 「取得日」
  - 「有効期限」（有効期間の規定が無ければ「なし」）
- 有効期限があるときは、更新の方法と期限を README に書く
- トップの `README.md` の資格の表に「状態」の列を足し（無ければ）、「合格（<YYYY-MM-DD>）」と書く

**不合格のとき:**
- 再受験の規定（待機期間、回数の制限）を確かめ、再受験日の候補を示す
- 苦しかったドメインと、ドメイン別の評価が低いドメインを優先して、学習プランを組み直す
  - README の学習プランの節を書き換える
  - 受験予定日は、`AskUserQuestion` で確かめてから書き換える
- 該当するドメインのチェックリストの `[x]` を `[ ]` に戻すかを聞く。戻すと、`/quiz` で確かめ直す流れに乗る

**発表待ちのとき:** 記録だけをして、発表後にもう一度 `/exam-retro` を実行するよう伝える。

## Step 4: コミットと報告

1. `docs(<exam>): 受験の振り返りを記録` でコミットする
2. チャットに次を書く
   - 記録したこと
   - 合格なら更新の期限
   - 不合格なら新しい学習プランの要点と、次の一手
