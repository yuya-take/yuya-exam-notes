# Exam Add

新しい資格のディレクトリを作る。作ったあとは、`/study`、`/quiz`、`/progress`、`/orchestrate` がそのまま使えるようにする。ディレクトリ構成は CLAUDE.md に従う。

## Step 1: 対象を決める

引数 `$ARGUMENTS` から、資格名・ディレクトリ名・受験予定日を読む。

- **ディレクトリ名:** 指定が無ければ、試験コードを小文字にしたものにする（例: `saa-c03`、`ccaf`）
- **同じ資格がある場合:** 既にあるディレクトリと同じ資格なら、新しく作らない。既存の README の情報が古くなっていないかを確かめ、更新する
- **資格名があいまいな場合:** 候補が複数ある（同じ名前で別のレベルがある、など）ときだけ、`AskUserQuestion` で候補から選んでもらう

## Step 2: 調べる

1. `exam-researcher` エージェントに、資格名を渡して調べさせる。返ってきた出典の URL のうち、試験ガイドは自分でも開いて、ドメインと比重を確かめる
2. 次の項目を集める

| 項目 | 例 |
|---|---|
| 名称と試験コード | |
| 問題数・試験時間・形式 | 選択式、記述、実技、監督付きか |
| 合格ライン | スコアの尺度も |
| 受験料・言語・受験方法 | |
| 出題ドメインと比重 | 公式の名前のまま |
| ドメインごとの出題項目 | タスク、知識、スキルなど、ガイドの粒度のまま |
| 公式の教材・模擬試験 | |
| 試験ガイドの版と日付 | |

3. 公式で確かめられない項目は、第三者の情報で補い、「（第三者情報・要確認）」と書く。どこにも無い項目は「未確認」と書く

## Step 3: ディレクトリを作る

`<exam>/README.md` を、[template.md](template.md) の形で作る。

- **チェックリスト:** 公式ガイドの出題項目を、1行1項目にする
  - 1項目は、ノート1つ分（A4 1〜2枚）にまとまる粒度にする
  - 大きすぎる項目は分け、小さすぎる項目はまとめる
  - 項目名は日本語にし、英語の正式名を括弧で添える
- **優先度:** 比重から付ける。上位3割は ★★★、次の4割は ★★☆、残りは ★☆☆
- **学習プラン:**
  - 受験予定日があれば、今日からの週数で組む
  - 無ければ、4週間で仮に組み、受験予定日は「未定」とする
- `notes/`、`quiz-log.md`、`mistakes.md` は作らない（使うスキルが、必要になったときに作る）

## Step 4: 登録とコミット

1. トップの `README.md` の資格の表に、1行足す
   - オーケストレータから任されたときは、この手順を飛ばす（オーケストレータが行う）
2. `docs(<exam>): <資格名>を追加` でコミットする

## Step 5: 報告

チャットには次だけを書く。
- 作ったディレクトリ
- 試験の要点（形式・合格ライン・ドメインと比重）
- 公式で確かめられなかった項目
- 次の一手（例: `/study <exam>`、または `/orchestrate <exam> のドメイン1をノート化`）
