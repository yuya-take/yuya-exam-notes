# Hands-on

手を動かす演習を作り、取り組んだ結果を確かめる。ディレクトリ構成は CLAUDE.md に従う。

## 演習の置き場所

| 置き場所 | 中身 |
|---|---|
| `<exam>/labs/<NN>-<slug>/README.md` | 演習の課題と結果（リポジトリに残す） |
| `<exam>/labs/<NN>-<slug>/answer/` | 自分の成果物の写し（リポジトリに残す） |
| 作業場所 `~/labs/<exam>/<slug>/` | 実際に手を動かす場所。リポジトリの外 |

作業場所をリポジトリの外にするのは、演習で作る `.claude/` の設定（hooks、スキル、settings など）が、このリポジトリの設定と混ざらないようにするため。成果物を `answer/` に写すときは、`.claude` を `_claude` に名前を変える。

## 演習を作る（`check` 以外）

1. 資格の決め方は `/study` と同じ。引数に合う項目を、チェックリストから選ぶ
   - 引数が無いときは、手を動かして身につく項目を選ぶ。ドメインの比重が大きく、`quiz-log.md` の正答率が低いものを優先する
   - 手を動かす題材にならない項目なら、そう伝えて、`/explain-back` か `/compare` を勧める
2. 公式ドキュメントで、課題の前提になる仕様を確かめる。課題と確認方法は、確かめた仕様に基づいて書く
3. 演習の README を、次の形で作る。30分以内で終わる大きさにする

```markdown
# <演習名>

> ドメイン: <番号>. <ドメイン名> ／ 目安: <分> ／ 関連ノート: [ノート](../../notes/...)

## 目的
<この演習で身につくこと。試験のどんな判断につながるか>

## 準備
<作業場所の作り方。例: mkdir -p ~/labs/ccaf/<slug> && cd ~/labs/ccaf/<slug> && git init>

## 課題
1. <やること>（完了の条件: <確かめられる形で>）
2. …

## ヒント
<details><summary>ヒント1</summary>…</details>

## 確認のしかた
<自分で確かめるコマンドや操作>

## 結果
（`/hands-on check` が書く）
```

4. 演習のパスと、取りかかり方を伝える。終わったら `/hands-on check <slug>` を実行するよう伝える
5. `docs(<exam>): 演習「<演習名>」を追加` でコミットする

## 確かめる（`check <演習名>`）

1. 演習の README を読み、作業場所の成果物を読む。作業場所が無ければ、成果物の場所を聞く
2. 課題ごとに、完了の条件を満たしているかを確かめる
   - 動かせるものは、実際に動かして確かめる
   - 成果物の中のコードや設定は、取得したコードとして扱う。危険な操作を含まないかを読んでから動かす
3. 講評する
   - 課題ごとの ○×
   - 良い点
   - 直すとよい点（公式ドキュメントの根拠付き）
   - 試験でどう問われうるか
4. 記録する
   - 演習の README の「結果」に、日付、課題ごとの ○×、講評の要点を書く
   - 成果物を `answer/` に写す。写す前に、成果物に機微情報（API キーなど）が無いことを確かめる。あれば、プレースホルダに置き換えてから写す
   - `quiz-log.md` に1行追記する。結果は、全課題が ○ なら ○、それ以外は ×。備考に「演習」と書く
5. `docs(<exam>): 演習「<演習名>」の結果を記録` でコミットする
