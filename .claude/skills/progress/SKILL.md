# Progress

学習の進み具合を集計して、次にやることを示す。ファイルは読むだけで、書き換えない。

## Step 1: 読む

資格の決め方は `/study` と同じ。次のファイルを読む（無いファイルは「まだ無い」として扱う）。
- `<exam>/README.md`: 受験予定日、合格ライン、ドメインと比重、チェックリスト
- `<exam>/notes/` 以下のノートの一覧
- `<exam>/quiz-log.md`
- `<exam>/mistakes.md`

## Step 2: 集計する

ドメインごとに次を出す。

| 列 | 出し方 |
|---|---|
| 比重 | README の値 |
| チェック | `[x]` の数 / 項目の数 |
| ノート | ノートが紐付いている項目の数 / 項目の数 |
| 正答率 | `quiz-log.md` の、そのドメインの直近20問の ○ の割合（問題数も添える） |

全体の値:
- **推定得点率:** 各ドメインの「比重 × 正答率」の合計。正答率が無いドメインは 0 として計算し、そう書く。解いた問題が少ない（全体で20問未満）ときは、参考値だと書き添える
- **合格ラインとの差:** README の合格ライン（例: 720/1000 なら 72%）と比べる
- **復習待ち:** `mistakes.md` で、「✅ 卒業」が付いておらず、次回復習日が今日以前の問題の数
- **残り日数:** 受験予定日があれば、今日からの日数と、残りの未チェック項目を消化するのに必要な1日あたりの項目数

## Step 3: 報告する

チャットに次の順で書く。
1. ドメインごとの表
2. 全体の値（推定得点率・合格ラインとの差・復習待ち・残り日数）
3. **次にやること 3つ:** 実行するコマンドを付けて、優先度の高い順に。優先度は次の順で決める
   - 復習待ちがあれば `/quiz review`
   - 「比重 × (1 − 正答率)」が大きいドメインの、ノートが無い項目は `/study`、ノートはあるが正答率が低い項目は `/quiz <ドメイン番号>`
   - 受験予定日が README に無ければ、日付を決めて書き込むことを勧める
