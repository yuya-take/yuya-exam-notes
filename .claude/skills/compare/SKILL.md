# Compare

混同しやすい概念の比較ノートを `<exam>/compare/<a>-vs-<b>.md` に作る。ディレクトリ構成は CLAUDE.md に従う。

## Step 1: 対象を決める

資格の決め方は `/study` と同じ。

**引数で比べるものが指定されたとき:** それにする（2〜5個）。

**引数が無いとき:** 次から、混同している組み合わせを探して3つまで提案する。`AskUserQuestion` で選んでもらう。
- `mistakes.md` で、自分の答えと正解が、似た概念どうしになっている問題
- ノートの「試験での見分け方」に出てくる組み合わせ
- 試験範囲で、同じ目的に複数の手段があるもの

同じ組み合わせの比較ノートが既にあれば、作り直さずに、足りないところを補う。

## Step 2: 調べる

それぞれの概念を、公式ドキュメントで確かめる。ノートがあれば先に読む。

## Step 3: 書く

```markdown
# <A> vs <B>

> 関係するドメイン: <番号> ／ 更新: <YYYY-MM-DD>

## 一言での違い
<1〜2文>

## 比較表
| 観点 | <A> | <B> |
|---|---|---|
| 目的 | | |
| いつ使う | | |
| いつ使わない | | |
| どこに書く・どう設定する | | |
| 実行のされ方（誰が、いつ） | | |
| コスト・制約 | | |

## どれを選ぶか
1. <問い>？ → はい: <A> ／ いいえ: 2へ
2. …

## シナリオで確かめる
1. <状況> → <選ぶもの>。理由: <短く>
（3〜5問。答えは `<details>` に入れる）

## 出典
- [ページ名](URL)
```

観点は、比べるものに合わせて足し引きしてよい。

## Step 4: 確かめて紐付ける

1. `fact-checker` エージェントに、比較ノートのパスを渡して確かめさせる。指摘があれば直す
2. 関係するノートの「試験での見分け方」の表の下に、`→ 比較: [<A> vs <B>](../../compare/<file>.md)` を足す（既にあれば何もしない）
3. `docs(<exam>): <A> と <B> の比較を追加` でコミットする

チャットには、比較ノートのパスと「一言での違い」だけを書く。
