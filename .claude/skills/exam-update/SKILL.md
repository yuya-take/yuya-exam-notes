# Exam Update

資格の公式情報に変更が無いかを調べ、学習ノートに反映する。ディレクトリ構成とチェックリストの書き方は CLAUDE.md に従う。

## Step 1: 今の内容を読む

引数 `$ARGUMENTS` から、対象の資格を決める。
- `all` のとき: すべての資格ディレクトリを対象にする
- 引数が無いとき: 資格が1つならそれ。複数あるときは聞く

資格ごとに `<exam>/README.md` から次を読む。
- 冒頭の出典の行（試験ガイドの名前、版、時点）
- 試験概要の表（受験予定日、最終確認日を含む）
- 出題ドメインと比重
- チェックリスト
- 変更履歴

## Step 2: 最新の公式情報を調べる

1. 主催団体の公式ページと、最新の試験ガイドを探して読む。WebSearch で探し、中身は WebFetch（無ければ web-fetch エージェント）で読む。資格が複数あるときは、資格ごとにサブエージェントに調べさせ、並列で進めてよい
2. 次の点を確かめる
   - 試験ガイドの版と日付
   - 試験コードの変更、新しい版の開始日、旧版の終了日（改訂の予告）
   - 問題数、試験時間、形式、合格ライン、受験料
   - 出題ドメインの名前・数・比重
   - ドメインごとの出題項目の追加・削除・変更
   - 公式の教材や模擬試験の追加
3. 公式の情報だけを、反映の根拠にする。第三者の情報で変更を知ったときは、公式で確かめられるまで「要確認」とする

**Claude など、製品そのものが試験範囲の資格の場合（例: `ccaf`）:** 試験ガイドが変わっていなくても、製品の仕様が変わってノートが古くなることがある。ノートの「出典」にある公式ページを見て、次のような変更が無いかを確かめる。
- 名前が変わった機能
- 廃止された機能
- 設定の書式の変更

ノートが多いとき（目安は10を超えるとき）は、全部を自分で調べず、怪しいノートの一覧を作るところまでにする。

## Step 3: 差分を示す

変更が無ければ、そう報告して Step 5 の「最終確認日」だけを更新する。

変更があれば、次の形で本文に示す。

```
## <資格名> の変更（試験ガイド v1.0 → v1.1）

### 試験概要
| 項目 | 今の README | 最新 | 出典 |
|---|---|---|---|
| 受験料 | $125 | $150 | <URL> |

### ドメインと比重
| ドメイン | 今 | 最新 |
|---|---|---|

### チェックリスト
- 追加: 2. <項目>
- 削除: 4. <項目>（ノートあり: notes/04-…/….md）
- 変更: 1. <旧> → <新>（ノートあり。内容の更新が必要）

### 改訂の予告
- 新しい版 <コード> が <日付> から。旧版は <日付> まで

### 古くなった可能性があるノート
- notes/02-…/….md: <何が変わったか>（出典: <URL>）
```

**受験予定日と改訂日の関係:**
- 受験予定日が、新しい版の開始日より前のとき: 今の版で学ぶのが正しい。新しい版の内容を反映するかどうかを、`AskUserQuestion` で聞く。推奨は「今の版のまま。改訂の予告だけ記録する」
- 受験予定日が未定のとき: どちらの版を目指すかを聞く

反映してよいかを、`AskUserQuestion` で聞く。分類ごと（概要・ドメイン・チェックリスト・ノート）に選べるようにする。

## Step 4: 反映する

承認された分だけを反映する。

**試験概要とドメイン:**
- 冒頭の出典の行を、最新の版と日付にする
- 表の値を書き換える
- 比重が変わったら、優先度（★）も付け直す

**チェックリスト:**
- **追加:** 該当するドメインに `- [ ]` で足す
- **削除:** 行を消さない。README の末尾の「範囲外になった項目」の節に移し、ノートへのリンクも残す。過去の学習の記録を失わないため
- **変更:** 項目名を書き換える。ノートへのリンクは残す。内容が大きく変わったときは、`[x]` を `[ ]` に戻す
- **ドメインの番号が変わったとき:**
  - `notes/` のディレクトリを `git mv` で付け直す
  - README と `mistakes.md` のリンクを直す
  - `quiz-log.md` と `mistakes.md` のドメイン番号を、新しい番号に書き換える
  - 新旧の番号の対応は、変更履歴に書く

**ノート:**
- 古くなったノートの、見出しの直後に次の1行を足す。本文は直さない。直すのは `/study` か、`/orchestrate` の `verify` タスクで行う
  ```
  > ⚠️ 要更新（<YYYY-MM-DD> /exam-update）: <何が変わったか>。出典: <URL>
  ```

**記録:**
- 試験概要の「最終確認日」を今日にする（行が無ければ「受験予定日」の下に足す）
- README の「変更履歴」の節に、新しいものを先頭にして追記する（節が無ければ「参考リンク」の前に作る）
  ```
  - <YYYY-MM-DD>: 試験ガイド v1.0 → v1.1。受験料 $125 → $150。2. に項目を1つ追加。ノート2つを要更新に
  ```

## Step 5: コミットと報告

1. コミットする
   - 変更があったとき: `docs(<exam>): 試験ガイド <版> に合わせて更新`
   - 変更が無かったとき: `docs(<exam>): 公式情報の確認日を更新`
2. チャットに次を書く
   - 反映したことの要約
   - 見送ったことと、その理由
   - 要更新のノートの数
   - 次の一手（例: `/orchestrate <exam> の要更新ノートを verify`、`/progress`）
