# Daily

今日の学習メニューを組み、了承されたら進める。ディレクトリ構成は CLAUDE.md に従う。

## Step 1: 状況を読む

資格の決め方は `/study` と同じ。次を読む（無いファイルは「まだ無い」として扱う）。
- `<exam>/README.md`: 受験予定日、比重、チェックリスト
- `<exam>/mistakes.md`: 「✅ 卒業」が付いておらず、次回復習日が今日以前の問題
- `<exam>/quiz-log.md`: ドメインごとの直近の正答率
- `<exam>/study-log.md`: 直近の学習と、続いている日数

## Step 2: メニューを組む

時間の目安は次のとおり。合計が指定の時間に収まるようにする。

| 中身 | 目安 |
|---|---|
| 復習（`/quiz review`）1問 | 2分 |
| 練習問題（`/quiz`）1問 | 2分 |
| ノート1つ（`/study`）を読んで確認問題を解く | 10分 |
| 自分の言葉で説明（`/explain-back`）1回 | 8分 |

優先順位:
1. **復習日が来た問題:** 最大10問。多いときは古いものから
2. **新しい項目:** 比重が大きく、まだノートの無い項目を1つ（`/study`）。ノートはあるが、まだ理解を確かめていない項目があれば、そちらを優先する（`/explain-back`）
3. **弱いドメインの小テスト:** 正答率がいちばん低いドメインから、残り時間で解ける問題数（`/quiz <ドメイン番号> <数>`）

受験予定日まで14日を切っていたら、新しい項目より、復習と小テストを優先する。7日を切っていたら、`/cheatsheet` を読む時間（10分）を入れる。

## Step 3: 示して始める

メニューを次の形で示す。

```
## 今日のメニュー（30分 ／ 受験まで 24日 ／ 連続 5日目）
1. 復習 4問（8分）
2. /explain-back 1-2 定番パターン（8分）
3. /quiz 4 7問（14分）: ツール設計と MCP の正答率が 55%
```

`AskUserQuestion` で、このまま始めるかを聞く。選択肢は、「始める」「復習だけにする」「メニューを変える（Other で書く）」。

始めることになったら、Skill ツールで、メニューのスキルを順に実行する。各スキルの記録とコミットは、そのスキルの手順に従う。

## Step 4: 記録する

終わったら（途中でやめたときは、そこまでの分を）`<exam>/study-log.md` に1行追記する。ファイルが無ければ、次のヘッダーで作る。

```markdown
# 学習の記録

| 日付 | 時間（分） | やったこと |
|---|---|---|
```

`docs(<exam>): 学習の記録を更新` でコミットする。

最後に、連続の日数と、明日の復習予定の数を1行で伝える。
